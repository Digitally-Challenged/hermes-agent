# Hermes dev context (distilled)

This file replaces AGENTS.md in Hermes' own prompt (it exceeds the context-file
cap). **`AGENTS.md` is the canonical dev guide** — read the relevant section
with read_file before making non-trivial changes: Contribution Rubric,
Footprint Ladder, Testing, TUI/CLI/Plugins/Skills architecture, Known Pitfalls.

## What this repo is

One agent core (`run_agent.py` — `AIAgent`, synchronous loop) across four
surfaces: classic CLI (`cli.py`), messaging gateway (`gateway/run.py` +
`gateway/platforms/`), Ink TUI (`ui-tui/` ↔ `tui_gateway/` stdio JSON-RPC),
Electron desktop app (`apps/desktop/`, talks to `tui_gateway`, NOT the TUI).
Tools live in `tools/*.py`, self-register via `tools/registry.py`, and are
exposed only when listed in a toolset in `toolsets.py`. Extend at the edges —
plugins (`plugins/`, `~/.hermes/plugins/`), skills (`skills/`,
`optional-skills/`), CLI subcommands (`hermes_cli/`) — not by growing the core
toolset (Footprint Ladder in AGENTS.md).

## Commands

```bash
source .venv/bin/activate
scripts/run_tests.sh                    # ALWAYS this wrapper, never bare pytest
scripts/run_tests.sh tests/gateway/     # subset; -v --tb=long pass through
# ui-tui/: npm run dev|build|typecheck|lint|fmt|test
```

## Non-negotiable invariants

- **Prompt caching is sacred**: never mutate past context, swap toolsets, or
  rebuild the system prompt mid-conversation (sole exception: compression).
  Cache-mutating slash commands default to deferred effect (`--now` to opt in).
- **Strict role alternation**: never two same-role messages; never inject a
  synthetic user message mid-loop.
- **Core is a narrow waist**: new model tools are a last resort — walk the
  Footprint Ladder (extend existing → CLI cmd + skill → check_fn-gated tool →
  plugin → MCP catalog → core tool).
- **`.env` is secrets only**; behavioral settings go in `config.yaml`
  (`DEFAULT_CONFIG` in `hermes_cli/config.py`). No new non-secret `HERMES_*`
  env vars.
- **Profile safety**: `get_hermes_home()` / `display_hermes_home()` from
  `hermes_constants` — never hardcode `~/.hermes`.
- **No change-detector tests** (no snapshots of model lists / config version
  literals / counts). **Tests must not write to `~/.hermes/`** (conftest
  redirects `HERMES_HOME`; profile tests also mock `Path.home()`).
- **Plugins never touch core files**; no new in-tree memory providers or
  third-party-product plugins (standalone repos instead).
- **Dependencies need upper bounds** (`>=floor,<next_major`; git URLs by SHA);
  run `uv lock` after changing `pyproject.toml`.

## Frequent gotchas

- New tool = TWO steps: `registry.register()` in `tools/<name>.py` AND a
  toolset entry in `toolsets.py`.
- Three config loaders: `load_cli_config()` (cli.py), `load_config()`
  (hermes_cli/config.py), raw YAML (gateway). Key works in CLI but not
  gateway → wrong loader.
- Slash commands: define once in `COMMAND_REGISTRY` (hermes_cli/commands.py);
  handlers in `HermesCLI.process_command()` (cli.py) and optionally
  `gateway/run.py`.
- Interactive menus: `hermes_cli/curses_ui.py`, never `simple_term_menu`.
- Skill authoring has hard standards (description ≤ 60 chars, section order,
  `platforms:` gating, tests in `tests/skills/`) — AGENTS.md "Skill authoring
  standards".
- Desktop-app tests run via repo-root `vitest`.

Full detail on any of the above: read AGENTS.md.
